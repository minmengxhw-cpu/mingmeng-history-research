# 国内主证据闭环矩阵（2026-08-15）

## 用途

本矩阵是九个国内专题的执行队列，不是资料数量报表。它把事件覆盖表、主证据追索队列和专题来源地图合并为一个可重算的状态文件：

```text
data/domestic/primary_gap_closure_matrix.json
```

生成命令：

```bash
python3 scripts/domestic/build_primary_gap_closure_matrix.py \
  --output data/domestic/primary_gap_closure_matrix.json
```

脚本只读元数据，不读取正文、不下载文件、不写 SQLite。`partial` 表示事件定义所需的一手材料仍有缺口，不表示该专题没有可研究资料。

## 状态纪律

- 目录、找寻手册和锁定查看器：只能是追索路线；
- 汇编和重印：可以支持文本线索和版本对读，但不能替代独立原件；
- OCR：默认是 `draft_ocr`，不能自动升级为正式引用；
- 同期报刊：可以作为独立交叉来源，但不能自动改称民盟内部文件或政府公文；
- 学术文章：属于 `scholarship_context`，不能替代事件定义原件；
- 只有原件或可靠版本、页级 provenance、文件 SHA256、人工复核和版本关系都满足，才允许关闭对应目标；
- 只有主证据、交叉证据、负向核查和研究包全部闭环，专题才可改为 `research_ready`。

## 每个目标的执行循环

1. 从矩阵选择一个 P0/P1 目标；
2. 在授权范围内取得或确认原件路线，先写入 staging manifest；
3. 核对来源、记录号、日期、页码、文件 SHA256 和访问边界；
4. 电子文本跳过 OCR，影像资料只做定向 OCR；
5. 做页级视觉复核和版本对照；
6. 通过 dry-run、数据库完整性、外键、FTS 和 manifest 校验；
7. 更新矩阵，只有证据条件全部满足时才关闭目标。

该矩阵的价值是让下一轮工作始终围绕“关闭哪一个可验证的证据缺口”，而不是围绕“再下载多少资料”。
