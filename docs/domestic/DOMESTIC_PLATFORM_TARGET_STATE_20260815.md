# 国内民盟史研究平台目标状态与执行合同

更新时间：2026-08-15

## 一、目标

国内平台要达到与海外平台相同的研究工作能力：研究者能够从一个问题出发，找到专题、筛选来源、定位到页、判断证据等级、生成可复核研究包，并明确知道哪些结论仍缺原件。

“资料多”不是目标；“检索路径完整、证据边界清楚、引用可以重放”才是目标。国内资料的特殊来源（报刊、档案影印件、民盟内部数据库、汇编、学术文章）不改变这条底线。

## 二、目标状态：四个门同时通过

| 门 | 达标含义 | 当前基线 |
| --- | --- | --- |
| 产品门 | 9 个专题均有入口、时间线、来源筛选、页级定位、研究包和缺口提示 | 已通过：9/9 导航可用 |
| 数据门 | 正式库完整性、外键、页表/FTS、来源 hash 和路径安全检查通过 | 已通过 |
| 证据门 | 每个专题至少有一条独立一手来源链，来源类型、页码、版本和复核状态可重放 | 未通过：9 个专题仍有开放主证据目标 |
| 研究门 | 基准问题的检索结果能够落到严格页级证据，且学术解释与原始材料分层 | 部分通过：研究包和学术层已在，原件闭环仍待补 |

因此，国内平台现在可以作为“带证据边界的研究导航与检索平台”使用，但还不能把九专题全部标成 `research_ready`。这两个状态必须在界面和报告中分开显示。

## 三、四阶段推进

### 阶段 A：原件缺口闭环（优先，约 2 周）

以 `data/domestic/primary_retrieval_queue.json` 为唯一执行队列，先处理 P0：

1. 1941 年成立宣言/成立会议的独立原件、馆藏档号和版本关系；
2. 1947-10-27 政府文件、1947-11-06 民盟公告及日期—主体—版本链；
3. 再从 1945 大会、1946 旧政协/拒绝国大、1948、1949 中选择最小可闭环单元。

每个目标都必须经过“取得或确认路线 → staging manifest → 来源和 hash → 页级视觉复核 → dry-run → 正式入库 → 完整性/FTS 回归”。浏览器数据库若能恢复可控访问，只做用户授权范围内的可见下载，并先进入 staging。

### 阶段 B：检索和研究工作流（约 1 周）

- 统一国内/海外专题卡片字段：时间、人物、组织、地点、来源类型、证据层级、复核状态；
- 每个检索结果显示命中理由、文档、页码、来源和证据徽章；
- 研究包支持“主张 → 来源 → 页”的反向追踪；
- 语义检索或模型摘要只能作为候选，最终回落到页级来源。

### 阶段 C：学术研究史与主题关系（约 1 周）

- 纳入 985 高校、中央研究机构、权威期刊和正式出版社的学术文章，标记为 `scholarship_context`；
- 建立人物、组织、地点、版本、争议和研究史字段；
- 学术文章可以解释争议和概念，但不能替代 L3/L4 原件；
- 对重复电子版、扫描版和 OCR 产物使用 hash 与替代关系管理，不因“已有电子文本”自动删除本地原件。

### 阶段 D：长期维护

- 每周关闭一个可验证的小缺口，而不是追求下载量；
- 每月跑一次全库完整性、来源可达性、路径泄漏和检索回归；
- 新资料先 staging，经过门禁再进正式库；
- 访问失效只更新状态和替代路线，保留原始 provenance 和历史审计。

## 四、每个专题的收口条件

专题只有同时满足以下条件，才可标为 `research_ready`：

1. 有至少一条独立一手来源链；
2. 每个关键主张有文档、页码/页界、来源 URL 或馆藏路线和文件 SHA；
3. OCR 已完成页级人工复核，或有可验证电子文本且跳过 OCR 的理由明确；
4. 汇编、转录、学术文章、同期报刊和负向核查分别标层；
5. 研究包、页面和回归测试都能复现同一条引用路径；
6. 正式库完整性、外键、FTS 和来源路径安全检查通过。

任何一个条件缺失，都只能保持 `partial` 或 `navigation_ready`，不能用后出汇编、镜像、OCR 草稿或学术摘要补成确定的一手结论。

## 五、下一轮交付物

下一轮不以“下载多少份”验收，而以以下交付物验收：

- 一个 P0 原件目标的 staging manifest 和访问审计；
- 该目标的页级来源地图、视觉复核记录和版本关系；
- 一次 dry-run 与正式库完整性/FTS 检查结果；
- 更新后的 `primary_gap_closure_matrix.json`、专题研究包和 parity 报告；
- 明确写出仍未闭合的原因，而不是将替代材料升级为原件。

## 六、当前边界

本地平台运行与回归已经通过，国内九专题具备导航和证据骨架；当前真正的瓶颈是原始材料访问和页级复核，不是页面框架或 SQLite 容量。Chrome 控制连接恢复后，优先从 1941 成立材料和 1947 公文/公告做定向检索；在连接恢复前，继续使用公开目录、找寻手册和已有本地资料推进路线审计，但不把它们记为原件闭环。
