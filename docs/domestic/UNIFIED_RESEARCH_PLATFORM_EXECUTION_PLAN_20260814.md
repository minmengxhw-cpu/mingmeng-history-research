# 国内外统一民盟研究平台：执行计划（2026-08-14）

## 1. 项目定位

这不是“把更多 PDF 放进数据库”，而是把国内资料做成与海外档案同等级的研究基础设施：

> 研究问题 → 专题事件 → 来源家族 → 原件或可靠版本 → 页级定位 → 引用门禁 → 国内外对读 → 可复现研究包

国内平台和海外平台的差别应体现在来源说明和访问权限上，而不应体现在研究流程上。国内官方网页、民盟全媒体数据库目录、文献汇编、同期报刊、档案影像、学术研究必须分层显示，不能合并成一个“资料数量”。

## 2. 当前判断

截至本计划日期，平台骨架已经可用，但内容尚未达到全部专题可正式研究的程度：

- 9 个国内专题已经有专题入口、研究问题路径、证据链和研究包；
- 120 条页级证据记录中，112 条通过严格引用门禁，但仍有开放的独立原件缺口；
- 36 条研究问题路径均可定位，9 个研究包结构校验通过，但当前不应把任何专题自动标记为 `research_ready`；
- 正式库约有 1,403 个文档、6,237 个页面，严格引用页为 201 页；
- 学术资料暂以元数据和候选全文为主。现有学术审计有 288 条记录，其中 99 条为学术文章；机构信号只能作为筛选提示，不能代替作者、职称、刊物和全文核验；
- 民盟全媒体数据库目前主要是目录级候选与访问路线，尚未形成可在本地复核的正文原件链。Chrome 自动化后端当前不可用，因此不得绕过登录或把目录当正文。

因此，下一阶段的目标不是继续扩大候选条目，而是把高价值资料逐项变成“可检索、可引用、可追溯、可比较、可复现”的研究单元。

本轮国内—海外能力对齐的可重算验收基线见：[DOMESTIC_FOREIGN_PARITY_ACCEPTANCE_20260814.md](DOMESTIC_FOREIGN_PARITY_ACCEPTANCE_20260814.md)。它把“导航可用、严格可引用、一手闭环”分开计数，后续每轮收口都以该口径和统一门禁为准。

## 3. 统一数据模型

每条资料都必须有以下状态字段，并在界面上分开计数：

| 层级 | 含义 | 能否支持正式引文 |
|---|---|---|
| `catalogue_only` | 目录、题名、记录号、入口链接 | 不能；只能做追索线索 |
| `navigation_only` | 已有本地文件或页级入口，但内容范围/页链未对账 | 不能；可做导航 |
| `draft_ocr` | OCR 草稿或机器抽取文本 | 不能；只能用于检索和定位 |
| `cross_source` | 同期交叉来源或可靠公开版本 | 依页级 provenance 和门禁决定 |
| `strict_citation` | 原图/可靠版本、页码、哈希、人工复核均齐备 | 可以，在边界内引用 |
| `research_ready` | 一个专题的主证据、交叉证据、负向核查和研究包都闭环 | 可以支撑专题研究输出 |

任何层级升级都必须保留来源、文件 SHA256、物理页/PDF 页、获取方式、版权/访问边界和复核记录；升级不等于覆盖原状态。

## 4. 五阶段路线

### 阶段 0：数据瘦身与准入冻结（1 周）

目标：停止无目标下载和整本 OCR，先让资料可治理。

产出：

1. 以文件 SHA256、来源 ID、版本和页数建立唯一 manifest；重复文件只建立复核组，不删除本地副本；
2. 逐条标记 `electronic_text`、`scan_only`、`page_anomaly`、`catalogue_only`；
3. 电子文本不做重复 OCR，已有完整页链只做定向人工复核，页数异常先做 provenance 对账；
4. 将全媒体数据库候选分为 P0/P1/P2：优先独立原件、会议记录、声明/函电、公报和同期报刊，长篇地方史志只作背景或线索；
5. 产出资料准入报告，确保 `body_read=false`、`formal_db_written=false`、`auto_delete=false` 等审计不变量没有被破坏。

验收：没有新的无来源文件进入正式库；每个候选都有下一步动作；OCR 队列可以解释“为什么做/为什么不做”。

### 阶段 1：现有资料可检索、可引用（2 周）

目标：先把已经拥有的同期报刊、公报、汇编和公开网页用好。

产出：

- 电子文本直接进入检索层；图像型 PDF 只对专题相关页做 PaddleOCR 或现有 OCR 的定向复核；
- 所有页级记录拥有来源文件和页码回链；
- FTS、页面导航、专题事件、研究问题和引用卡互相可回链；
- 对汇编重刊明确标记为“重刊版本”，不冒充独立原件；
- 建立 1941—1949 年份/专题/来源家族覆盖矩阵。

验收：研究者从一个问题页出发，三步以内能到达页级来源；机器 OCR 不能直接进入严格引用层；SQLite integrity、外键、FTS 和 manifest 全部通过。

### 阶段 2：三个旗舰专题闭环（4—6 周）

目标：用跨时期样板证明国内平台能产生真正的研究成果，而不是只有目录。

优先选择：

1. **1941 成立与早期组织**：成立宣言、早期政治主张、同期报刊、组织/会议记录；
2. **1946 政治选择与李闻事件**：拒绝参加国民大会的正式声明/函电、同期报刊、李公朴和闻一多相关官方或同期材料；
3. **1947—1949 组织受压、恢复与新政协**：政府公报/公函、同期报刊、1948 三中全会和 1949 共同纲领相关材料。

每个旗舰专题至少要形成：

- 1 组主证据；
- 1 组同期交叉证据；
- 1 组负向核查或未发现记录；
- 1 张版本关系表；
- 1 个可复现研究包；
- 1 张与海外档案的对读卡。

只有全部满足，才允许把该专题标记为 `research_ready`。

### 阶段 3：学术研究层（4 周，与阶段 2 并行）

目标：把优秀学术研究用于解释史学争议和发现档案线索，但不替代一手材料。

分层规则：

- S：中央文献/档案机构或权威史料整理；
- A：可核验的高水平学术文章、专著、学位论文；
- B：一般学术或地方研究，作为补充；
- C：线索、媒体、百科或来源不稳定材料，不进入正式论证。

对“985/重点院校教授”类资料，必须逐项补齐作者、机构、刊物/学位、年份、稳定链接和全文状态；机构信号未核验前只能标记为候选。学术文章的职责是提供概念、争议、研究史和反查路径，不能把二次叙述写成一手证据。

验收：每篇 A/S 资料有独立书目信息和专题匹配理由；全文缺失时仍能作为书目线索，但不会产生虚假的引用页。

### 阶段 4：国内外对读与研究输出（4 周）

目标：使国内外资料在同一研究问题下互相校正。

统一输出模板：

1. 研究问题和时间边界；
2. 国内主证据及其访问/版本限制；
3. 海外档案的记录者、身份和形成场景；
4. 同期交叉、矛盾和沉默；
5. 证据等级与未闭环目标；
6. 可复现研究包和引用书目。

重点不是追求“中外各一条”，而是标明两类来源是否独立、是否同一版本、是否受到传播链影响。

### 阶段 5：发布与长期维护（2 周后转常态）

目标：形成内部研究库、公开展示版和可回滚的数据发布机制。

- 内部库保留授权资料和完整审计；公开版只展示允许公开的元数据、页级入口和引用边界；
- 每次导入都有备份、manifest、哈希和回滚记录；
- 每月做来源链接、授权状态、重复文件和研究包回归检查；
- 数据库、OCR 大文件和原始私有资料留在本地数据盘，不直接推送 GitHub。

## 5. 访问民盟全媒体数据库的正确接入方式

该平台应作为一个高价值来源家族接入，而不是作为“自动爬虫目标”：

1. 用户在已授权浏览器中登录；
2. 只从用户明确授权的详情页下载正文 PDF/完整页图/音视频或保存页级截图；
3. 同时写入 `source_url`、记录号、题名、访问时间、文件 SHA256、页数和访问/版权状态；
4. 先进入本地 staging，不直接写正式 SQLite；
5. 电子文本先跳过 OCR；图像资料才进入定向 OCR；
6. 人工逐页核验后，按 `strict_citation` 门禁升级；
7. 目录仍然保留为目录，不因下载失败或登录限制而伪造正文。

当前 Chrome 自动化后端不可用时，唯一合理的动作是保留高价值追索队列，等待用户在授权浏览器完成下载；不读取 Cookie、不绕过登录、不把访问失败写成资料缺失。

## 6. 项目角色与循环

- **Codex**：架构、数据契约、准入门禁、验收、合并和发布收口；
- **本地执行 Agent**：批量清点、文本抽取、OCR、manifest、候选去重和报告生成；
- **人工/授权浏览器**：只负责需要会话或视觉判断的下载和页面确认；
- **研究者**：只在严格门禁通过后使用引用卡和对读卡。

循环固定为：

> 盘点 → 分层 → 小批处理 → 校验 → 验收 → 更新缺口 → 下一批

不得用“运行了很久”“OCR 页数很多”“候选条目增加”替代验收。

每轮收口统一运行：

```bash
python3 scripts/domestic/validate_unified_research_platform.py \
  --output work/domestic/unified_platform_gate_20260814/REPORT.json
```

该门禁的 `status=PASS` 只表示平台结构、来源准入、数据库 manifest、专题包、研究问题路径和公开边界一致；同时必须查看 `research_content_status`。只要仍有未闭环的一手资料，它就会保持 `OPEN_PRIMARY_GAPS`，不会把基础设施通过误报为史料研究完成。

## 7. 最终完成定义

项目达到可交付状态，至少需要：

- 1941—1949 的国内专题均有明确研究问题、来源家族和开放原件缺口；
- 至少三个旗舰专题达到 `research_ready`；
- 每个旗舰专题有主证据、同期交叉和负向核查；
- 资料、页面、事件、人物、组织、研究问题和国内外来源能够互相回链；
- 研究包可在另一台 Mac 恢复并通过完整校验；
- 公开展示不会泄露原始私有正文；
- 所有“未完成”都能说明原因：未取得、目录-only、页链异常、OCR 草稿、权限限制或等待人工复核。

真正的收口标准不是“资料库变大”，而是研究者能对一个具体问题给出：依据哪一份材料、哪一页、哪一个版本、由谁形成、如何复核，以及目前还不能确定什么。
